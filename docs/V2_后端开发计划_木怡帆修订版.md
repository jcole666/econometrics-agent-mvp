# 计量建模 Agent MVP V2 后端开发计划（木怡帆修订版）

## 1. 我的角色定位

我是木怡帆，V2 阶段主要负责后端开发。后端需要把现有 MVP 从“模型推荐 + 代码模板生成”升级为“能对话、能自动识别变量、能真实运行基础模型、能生成分析报告”的可演示版本。

后端核心任务不是一次性实现所有复杂计量模型，而是先保证主流程完整、稳定、可联调、可演示。

## 2. V2 后端总体目标

V2 后端围绕 4 个新接口展开：

| 接口 | 方法 | 用途 | 优先级 |
|---|---|---|---|
| `/chat` | POST | 大模型对话，回答模型、变量、代码和结果相关问题 | 必做 |
| `/infer-variables` | POST | 根据研究问题和字段信息自动识别 Y / X 等变量 | 必做 |
| `/run-model` | POST | 上传数据并真实运行模型，第一版优先支持 OLS / Logit | 必做 |
| `/generate-report` | POST | 根据研究问题、模型和结果生成 Markdown 分析报告 | 必做 |

一句话目标：

> 先把“上传数据 → 自动识别变量 → 推荐模型 → 运行基础模型 → 对话解释 → 生成报告”的主链路跑通。

## 3. 范围控制原则

因为后端只有我一个人负责，且 7 月 8 日是开发 DDL，后续还要留出一周测试时间，所以 V2 必须控制范围。

### 3.2 尽量完成

- DID 变量检查清单；
- 对回归结果的中文解释；
- MaaS 不可用时的规则降级逻辑；

### 3.3 有时间再做

### 3.4 第一版暂不承诺

- 不做数据库级长期记忆。

这样做的原因是：第一版要求能 work 起来，主流程稳定比模型覆盖面更重要。

## 4. 核心安全原则

`/run-model` 只调用后端预定义的 `statsmodels` / `linearmodels` API。

严格禁止：

```text
exec 用户代码
eval 用户输入
运行用户上传的脚本
把大模型生成的代码直接拿去执行
```

允许：

```text
读取用户上传的 CSV / Excel
校验列名
按固定函数运行 OLS / Logit / DID 简化模型
返回结构化结果
```

## 5. 新增接口设计

### 5.1 POST `/chat`

用途：让用户围绕当前数据、推荐模型、生成代码和运行结果继续追问。

请求示例：

```json
{
  "message": "为什么推荐 OLS 而不是 Logit？",
  "history": [
    {"role": "user", "content": "教育水平是否影响收入？"},
    {"role": "assistant", "content": "推荐 OLS。"}
  ],
  "context": {
    "data_columns": ["income", "education", "experience", "gender"],
    "recommended_model": "OLS",
    "generated_code": "import statsmodels.api as sm...",
    "model_results": null
  }
}
```

响应示例：

```json
{
  "reply": "推荐 OLS 是因为 income 是连续型变量，当前问题关注解释变量对收入的线性影响...",
  "provider": "huawei_maas",
  "maas_error": null
}
```

实现策略：

- 优先调用华为云 MaaS；
- 每次请求都把“这是计量建模 Agent MVP”的系统提示词传给大模型；
- 把当前字段、推荐模型、代码、结果作为上下文传给大模型；
- MaaS 不可用时，返回基于规则的兜底回复。

### 5.2 POST `/infer-variables`

用途：根据研究问题和字段信息自动识别变量配置。

请求示例：

```json
{
  "research_question": "教育水平和工作经验是否影响收入",
  "columns": [
    {
      "name": "income",
      "dtype": "int64",
      "sample_values": ["20000", "15000", "8000"]
    },
    {
      "name": "education",
      "dtype": "int64",
      "sample_values": ["16", "14", "12"]
    }
  ]
}
```

响应示例：

```json
{
  "dependent_variable": "income",
  "independent_variables": ["education", "experience", "gender"],
  "entity_column": null,
  "time_column": null,
  "treatment_column": null,
  "running_variable": null,
  "instrument_variable": null,
  "reasoning": "研究问题中收入是结果变量，教育水平和工作经验是主要解释变量。",
  "provider": "huawei_maas",
  "maas_error": null
}
```

实现策略：

- 优先使用 MaaS 进行变量识别；
- 要求 MaaS 只返回 JSON；
- 校验大模型返回的变量名必须存在于 `columns` 中；
- MaaS 不可用时使用规则降级：
  - `income / wage / salary / 收入 / 工资` 优先识别为 Y；
  - `id / 编号 / entity` 优先识别为个体 ID；
  - `year / time / date / 年份 / 时间` 优先识别为时间变量；
  - 其他数值型变量优先作为 X。

### 5.3 POST `/run-model`

用途：真实运行计量模型，并返回结构化回归结果。

第一版支持范围：

```text
必须支持：OLS
尽量支持：Logit
有余力支持：DID 简化版
暂不强制支持：RDD / IV-2SLS 真实运行
```

请求格式：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | File | 是 | CSV / Excel 数据文件 |
| `model_type` | string | 是 | `OLS` / `Logit` / `DID` 等 |
| `dependent_variable` | string | 是 | 被解释变量 Y |
| `independent_variables` | string | 是 | 解释变量 X，英文逗号分隔 |
| `entity_column` | string | 否 | 面板个体 ID |
| `time_column` | string | 否 | 时间列 |
| `treatment_column` | string | 否 | 处理组或处理变量 |
| `running_variable` | string | 否 | RDD 断点变量 |
| `instrument_variable` | string | 否 | IV 工具变量 |

响应示例：

```json
{
  "model_type": "OLS",
  "success": true,
  "results": {
    "sample_size": 100,
    "r_squared": 0.423,
    "r_squared_adjusted": 0.401,
    "f_statistic": 19.52,
    "f_pvalue": 0.0001,
    "coefficients": [
      {
        "variable": "education",
        "coefficient": 1250.5,
        "std_error": 312.3,
        "t_statistic": 4.00,
        "p_value": 0.0002,
        "ci_lower": 630.1,
        "ci_upper": 1870.9
      }
    ]
  },
  "warnings": ["已自动去除 3 行缺失值"],
  "error": null
}
```

失败响应仍然返回 200，但 `success=false`：

```json
{
  "model_type": "RDD",
  "success": false,
  "results": null,
  "warnings": [],
  "error": "RDD 真实运行将在后续版本支持，当前版本可提供代码模板和检查清单。"
}
```

实现策略：

- 复用统一数据读取工具读取 CSV / Excel；
- 校验模型类型是否合法；
- 校验所有变量都存在于 DataFrame 中；
- 对参与建模的变量强制转为数值型；
- 自动删除缺失值并记录 warning；
- OLS 使用 `statsmodels.OLS(...).fit(cov_type="HC1")`；
- Logit 使用 `statsmodels.Logit(...).fit(disp=False)`；
- 捕获异常，返回 `success=false + error`，避免接口直接 500。

### 5.4 POST `/generate-report`

用途：根据研究问题、模型类型和模型结果生成 Markdown 分析报告。

请求示例：

```json
{
  "research_question": "教育水平和工作经验是否影响收入",
  "model_type": "OLS",
  "model_results": {
    "sample_size": 100,
    "r_squared": 0.423,
    "coefficients": []
  },
  "inference_notes": "用户备注，可选"
}
```

响应示例：

```json
{
  "markdown": "# 计量分析报告\n\n## 研究问题\n教育水平和工作经验是否影响收入\n\n## 模型选择\n本次推荐 OLS..."
}
```

实现策略：

- 第一版只返回 Markdown；
- 不强制生成 Word；
- 优先使用模板生成稳定结构；
- 如 MaaS 可用，可让大模型润色解释部分；
- MaaS 不可用时，使用模板化中文报告。

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| MaaS 不稳定或不可用 | 所有大模型能力都提供规则/模板降级 |
| DID/RDD/IV 时间不够 | 第一版只做检查清单和代码模板，不强制真实运行 |
| 前端等后端接口 | 先把接口契约发给前端，前端可以 mock 数据并行开发 |
| 运行模型报错多 | 先只支持 OLS / Logit，控制输入范围 |
| 报告生成太复杂 | 第一版只输出 Markdown，不做 Word |
| 7 月 8 日前功能不稳定 | 7 月 7 日后停止加功能，只修 bug |
